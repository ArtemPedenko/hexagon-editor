## Решения и [Уточнить]

- Базовый ориентир совместимости — `@gravity-ui/markdown-editor` 15.45.0, исходник MIT (commit `fcb1c73561e9d0ee04a8f2a73308c4fadd1cff14`).
- Результат — самостоятельный пакет `@gravity-ui/vue-markdown-editor` для Vue 3, а не React-обёртка.
- Сохраняем Markdown/YFM-first модель и движки ProseMirror (WYSIWYG) и CodeMirror 6 (markup); React и React-only зависимости в итоговый пакет не входят.
- Публичная интеграция будет Vue-компонентом `MarkdownEditor` и composable `useMarkdownEditor`; инстанс сохранит событийную модель, `getValue`, `setEditorMode`, вставку, фокус и уничтожение.

- Каждый инкремент завершается typecheck, unit-тестами и актуализацией этого плана; визуальная проверка выполняется в playground до перехода дальше.

## Описание

React-библиотека Gravity UI Markdown Editor совмещает визуальный редактор Markdown/YFM, исходный markup-режим, split-view и набор расширений, но не предоставляет Vue-интеграции. Требуется создать MIT-совместимый Vue 3-порт с аналогичной функциональной областью и отдельным пакетом, не встраивающим React. Результат принимается по воспроизводимой матрице API и сценариев исходной библиотеки в локальном playground.

## Визуальная и интерактивная концепция

- **Визуальный тезис:** спокойное рабочее поле Gravity UI — плотный, но читаемый редактор без декоративных карточек.
- **План интерфейса:** панель режима и действий, рабочая область редактора, контекстные меню/инспекторы, тестовый контент и состояния ошибок.
- **Интеракции:** мгновенное переключение WYSIWYG/markup/split, контекстная панель для выделения, плавное открытие preview и popover-меню без потери фокуса.

## Технические детали

Структура — pnpm workspace: `packages/vue-markdown-editor` (публикуемая библиотека) и `apps/playground` (ручная и визуальная проверка). Пакет использует ESM, TypeScript strict, Vue 3.5+, ProseMirror и CodeMirror 6. Нужно сохранить уведомление об исходной MIT-лицензии в документации и публикуемом пакете.

## Критерии приёмки

1. Каждый пункт плана имеет статус и выполняется строго после завершения предыдущего пункта.
2. Финальный пакет не имеет runtime-зависимости от `react`, `react-dom` или React renderer.
3. Пользователь может создать редактор из Vue, переключить три режима, получить эквивалентный Markdown/YFM и использовать заявленные расширения.
4. Playground демонстрирует основной сценарий, ошибочные/пустые состояния и optional-расширения.
5. В финале проходят typecheck, unit, integration, e2e и визуальные проверки, а API-сверка не содержит незафиксированных расхождений.

## Тестирование

1. После каждого инкремента: `pnpm typecheck`, относящиеся unit-тесты и ручная проверка playground.
2. Перед завершением: Markdown round-trip, редакторские команды, переключение режимов, clipboard/upload, клавиатура и доступность; Chrome/Firefox/WebKit e2e и визуальная регрессия.

## Риски и зависимости

Полный порт содержит 986 TS/TSX/SCSS исходных файлов и React-bound view code, поэтому нужен поэтапный перенос с тестовой матрицей, а не механическая конвертация. Optional peer-расширения и GPT зависят от внешних пакетов/пользовательских обработчиков. Запуск проверки требует Node 20.19+ и pnpm 10+.
